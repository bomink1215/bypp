# 회고 — 오늘 뭐 먹지? (BYPP)

> 지금 여기서, 딱 맞는 한 끼. 위치 기반 메뉴 추천과 "여럿이 같이 고르기" 서비스.
> 배포: https://bypp-nine.vercel.app

---

## 1. 개발하며 부딪힌 문제

### 가게 세부 정보(메뉴·영업시간)를 가져올 수 없었다

- **문제** — 카카오 로컬 API가 주는 건 가게 이름·업종·주소·좌표·전화·카카오맵 링크가 전부다.
  메뉴판, 영업시간, 가격, 별점, 사진은 없다. 대체 소스도 모두 막혀 있었다.
  - Google Places 영업시간·별점: 유료 등급, 결제수단 등록 필수
  - OpenStreetMap: 강남역 일대 음식점 1,531곳 중 35곳(2.3%)만 영업시간 보유
  - 공공데이터 음식점 인허가 정보: 영업시간 컬럼 자체가 없음
  - 포털 크롤링: 약관 위반 소지 → 채택하지 않음
- **해결** — 우리가 줄 수 없는 정보는 **카카오맵으로 안내**했다. 가게 카드의 가장 큰 버튼을
  "카카오맵에서 보기 — 영업시간 · 메뉴 · 사진 확인하기"로 두어, 무엇을 확인하러 가는지까지 적었다.
- **배운 점** — 데이터가 없으면 추천도 그만큼만 약속해야 한다. 카카오가 `한식 > 국밥`까지만
  알려주므로 "고기국밥"이 아니라 "국밥"까지만 추천한다. **추천이 약속하지 않은 것은 어긋날 수 없다.**
  이 원칙을 `npm run verify:seed`로 강제했다(메뉴 이름으로 카카오 검색을 해서 가게가 잡혀야 편입).

### 여럿이 고를 때 선택이 양극단으로 갈리면?

- **문제** — "A는 매운 걸 원하고 B는 매운 걸 못 먹는다"처럼 조건이 부딪히면 누구 편을 들어야 하나.
  또 조건을 교집합으로 걸러내면 세 명이 하나씩만 걸어도 후보가 50개에서 1개로 붕괴했다.
- **해결** — **"못 먹는 것"(제약)과 "오늘의 선호"(선호)를 다른 종류의 정보로 나눴다.**

  | | 합치는 법 | 조건이 부족할 때 |
  |---|---|---|
  | 못 먹는 것 | 한 명이라도 못 먹으면 전체 제외(합집합) | 절대 풀지 않는다 |
  | 오늘의 선호 | 가장 불만인 사람의 만족도를 최대화 | 점수만 깎고 지우지 않는다 |

  B의 제약이 먼저 이기고, A의 선호는 남은 후보 안에서 작동한다. 매움 3과 순함 0이 부딪히면
  양 끝이 아니라 중간 매운맛이 뽑힌다. 서로 반대되는 선호(고기 있음 vs 없음)는 해제하고
  이름을 화면에 띄운다 — 조용히 넘어가면 사용자는 자기 조건이 지켜진 줄 안다.

### 배포 과정에서 겪은 것

- **Vercel 환경변수** — `NEXT_PUBLIC_`이 붙은 값은 **빌드할 때** 코드에 박히므로 변수를 추가한 뒤
  반드시 재배포해야 한다. 또 "Secret" 유형으로 만든 변수는 Production 값이 따로 비어 있어 서버가
  빈 값을 읽었다. 배포된 JS 번들과 API 응답을 직접 확인해 원인을 찾았다.
- **도메인** — `bypp.vercel.app`은 다른 사람의 프로젝트였다. 우리 주소는 `bypp-nine.vercel.app`.
  카카오 로그인 Redirect URI와 지도 SDK 도메인은 **도메인마다 따로** 등록해야 한다(KOE006).
- **보안 점검** — 배포 전 점검에서 로그인 후 돌아갈 주소에 `/\evil.com`을 넣으면 외부 사이트로
  토큰이 넘어가는 문제를 찾아 고쳤다. 문자열 모양이 아니라 **실제로 URL을 해석해 origin을 비교**한다.
  비밀 키가 브라우저 번들에 없는지, 공개 키로 DB가 읽히지 않는지(RLS)도 확인했다.

## 2. 심사위원 피드백

| 피드백 | 대응 |
|---|---|
| 커뮤니케이션(같이 고르기) 기능이 좋다 | 방 공유 버튼, 모두 투표하면 자동 마감, 결정 알림, 가게 투표로 강화 |
| 별점·영업시간을 긁어와서 쓰면 좋겠다 | 크롤링은 약관 위반 소지가 있어 채택하지 않음. 별점은 **자체 평가 DB**로 대신(아래 1번) |
| 음성 인식이 되면 좋겠다 | 아직 반영하지 않음. 조건 입력이 버튼 중심이라, 음성으로 "매운 국물 요리"를 말하면 조건으로 바꾸는 방식을 검토할 수 있다 |

## 3. 데모 마켓 피드백과 반영

| # | 피드백 | 결과 |
|---|---|---|
| 1 | 별점순 정렬 | 🔶 자체 평가 DB로 대체 |
| 2 | 메뉴판 사진을 앱 안에서 | ❌ 불가 |
| 3 | 가격대 옵션 | ✅ 메뉴별 평균 가격대 |
| 4 | 가까운 순으로만 나오는 가게 목록 | 🔶 전문점 우선 정렬 |
| 5 | 노트북에서 지도로 위치 고르기 불편 | ✅ 장소 이름 검색 |
| 6 | 기준·식재료를 늘려 달라 | ✅ 식재료 세분화, 밥·면, 가격대, 메뉴 추가 |
| 7 | 조작할 게 많다 | ✅ 선호 조건 접기 |
| 8 | 깊이와 차별성이 부족하다 | ✅ 나의 먹로그 |

### 1·2번 — 별점, 메뉴판 사진

카카오맵 API가 가게별 세부 내역을 제공하지 않아 그대로는 할 수 없었다. 메뉴판 사진은 카카오
가게 페이지를 앱 안에 띄우는 실험까지 해봤지만 내용이 비어서 반영하지 못했다.

별점은 **자체 평가 데이터베이스를 구축**하기로 했고, 8번 피드백과 연결했다. 방문한 가게에 별점과
후기를 남기면 일종의 **"업적 카드"**가 되어 **"나의 먹로그"**에 쌓인다. 친구와 함께한 식사는 친구들의
이름도 같이 기록해 **추억을 간직하는 기능**이 되고, 동시에 별점이 모여 가게 목록에 "이 앱 평점"으로 보인다.

- 가게를 고른 순간 "여기로 정했어요"로 먹로그의 **방문한 가게**에 먼저 담는다. 먹으러 가서 브라우저를
  닫아도 나중에 먹로그에서 후기를 쓸 수 있다. 방에서 가게까지 정하면 참가자마다 자동으로 담긴다.
- 배지 7종(첫 한 끼, 열 끼, 함께라서, 밥친구 부자, 단골, ○○ 마니아, 탐험가)은 기록에서 자동 계산한다.
- 함께한 사람의 이름은 **내 먹로그에만** 남고 공개 후기에는 나가지 않는다.
- 로그인 없이도 쓸 수 있고, 로그인하면 계정에 묶여 다른 기기에서도 보인다.

### 3번 — 가격대

API로 메뉴 가격을 받아올 수 없어서, **메뉴별 보통 가격대**를 1만원 이하 / 1~2만원 / 2만원 이상으로
나눠 분류했다. 가게 가격이 아니라 메뉴 기준이라 "가게마다 다를 수 있어요"라고 함께 안내한다.

### 4번 — 가게 정렬

별점 같은 기준이 없어 다양한 정렬이 어려웠다. 대신 **카카오 세부 업종이나 점포명에 메뉴명이 있으면
그 메뉴의 전문점**으로 보고 **전문점을 위에, 같으면 가까운 순**으로 정렬했다.
(예: "국밥" 추천에서 `한식 > 국밥`인 ○○국밥이 일반 한식집보다 먼저)
짬뽕처럼 업종이 "중식"으로만 나오는 메뉴는 전문점을 가릴 수 없어 여전히 거리순이다.

### 5번 — 위치 고르기

지도를 끌어서만 찾던 방식에 **장소 이름 검색**을 더했다. "강남역", "코엑스"처럼 역·건물 이름으로 찾아
지도를 옮기고, 확정은 기존처럼 화면 중앙 핀으로 한다. (동네 이름을 검색하면 동네 대신 근처 명소가
나오는 한계가 있다.)

### 6·7번 — 서로 충돌하는 피드백

"기준을 늘려 달라"와 "조작할 게 많다"는 정반대다. 문제가 무엇인지 따져보니, **선호 조건이 모두
펼쳐져 있어서** 실제로는 "상관없음"으로 두어도 되는데도 **골라야 할 게 너무 많다는 인상**을 준다고
판단했다.

- 선호 조건을 **"오늘의 선호 조건 눌러서 선택하기"로 접어두고**, 누르면 펼쳐지게 바꿨다.
  설정한 조건이 있으면 개수를 표시한다. (방에서는 조건을 내는 게 목적이라 펼친 채로 시작)
- 그렇게 공간을 만든 뒤 기준을 늘렸다.
  - 식재료: 고기/해산물/밀가루 → 고기를 **돼지·소·닭**으로 세분화, **달걀·유제품** 추가
  - 못 먹는 것에도 돼지고기·소고기·닭고기·달걀·유제품 추가
  - **밥 / 면 / 그 외** — "밥 먹을까 면 먹을까"라는 가장 흔한 고민을 기준으로
  - **가격대**(3번)
  - 메뉴 51개 → **64개**(냉면·막국수·샤브샤브·쌈밥·죽·도시락·해물탕·아귀찜·쭈꾸미·낙지·훠궈·타코·케밥).
    후보 17개를 카카오에서 실제로 검사해 가게가 잡히는 것만 넣었다(덮밥·브런치·채식·비건은 탈락).

## 4. 남은 과제

- **메뉴판 사진·영업시간** — 데이터 소스 문제가 풀리기 전에는 카카오맵 안내가 한계
- **음성 인식** — 심사위원 제안. 말로 조건을 넣는 입력 방식
- **평점 신뢰도** — 지금은 로그인 없이도 후기를 쓸 수 있어 조작에 약하다. 실제로 조작이 보이면
  로그인 필수·신고 기능을 검토
- **채식 메뉴** — "고기 전체 + 해산물"을 못 먹는 것으로 두면 후보가 크게 줄어든다. 카카오 업종으로
  채식 식당을 가릴 수 없어 시드로 풀지 못했다
